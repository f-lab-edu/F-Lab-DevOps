# A6 보고서 검증·실패 처리·보안 시험

- 확인일: 2026-10-01
- 상태: 로컬 합성 입력과 모의 모델 응답으로 구현·검증 완료. 실환경 자료와 실제 API 호출은 이 단계의 시험에 사용하지 않았다.
- 선행 조건: A5 Responses 어댑터를 사용한다. HolmesGPT의 동등 조건 비교는 A5의 별도 미완료 항목이다.

## 검증 경계

`contracts.py`의 `AnalysisReport`는 필수 필드, 원인 후보 최대 3개, `SuggestedAction.execution_status=not_executed`를 강제한다. `reports.py`는 사건·실행 ID, 대상·시간 범위·입력 hash와 보고서의 일치를 확인한다. AI 보고서의 사실·가설에는 해당 실행에서 도구로 실제 제공한 `available` 증거 ID만 허용한다. 제안 문장에서 `재시작 완료`처럼 조치를 이미 실행했다고 주장하면 거부한다. 이 문장 검사는 명백한 표현을 막는 보조 장치이며, 모든 자연어 주장의 참·거짓을 판별하지는 않는다.

모델 출력의 비밀값 패턴과 제어 문자는 저장 전에 거부한다. 사용자용 Markdown에서는 외부 URL·위험한 링크 스킴, 터미널 제어 문자와 방향 제어 문자를 제거하고 Markdown 특수 문자를 이스케이프한다. 원본 모델 초안은 실패 기록에 저장하지 않는다. 악성 로그 문장을 본 모의 모델이 `shell` 도구를 요청하는 경우에도 실행기가 허용 목록 밖 요청을 거부하고 감사 기록의 인자를 숨기는지 확인했다. 이 시험은 실제 모델이 악성 지시를 항상 무시한다는 품질 보증은 아니다.

## 실패와 부분 결과

모델 인증·할당량·네트워크 오류, 시간 초과 또는 건당·UTC 일일 예산 제한이면 새 모델 호출을 늘리지 않고 검증된 저장 증거로 규칙 분석을 수행한다. 보고서는 `analysis_status=partial`, `execution.mode=rules`, `engine=rules-fallback-v1`로 저장하고 사건 metadata는 `status=partial`과 원래 AI 실패 코드, 이미 알려진 사용량을 보존한다. 도구 조회가 있었다면 `tool-audit.json`도 보존한다. 규칙 분석은 저장된 합성 묶음 전체를 사용하므로, AI에 전달된 증거만 본 결과라고 표시하지 않는다.

형식 오류·허위 근거·민감한 출력·실행 성공 주장처럼 보고서 계약을 위반한 AI 결과는 규칙 보고서로 덮지 않고 `failed`로 남긴다. 사용자 취소는 `cancelled`로 남긴다. 부분 보고서의 CLI 조회는 실패 이유와 규칙 분석임을 보여주고 종료 코드 1을 반환한다. `show --format json`은 부분 결과일 때만 `status`, `failure_reason`, `report`를 함께 출력한다. 정상 완료의 JSON 형식은 그대로 유지한다. 내부 JSON 시각은 UTC, 사람이 읽는 Markdown 시각은 KST다.

## 로컬 확인

고정 의존성의 Pydantic 2.13.5 환경에서 전체 단위 시험 **60건 통과**. 사건·입력 불일치, 허위/미제공 근거, 조치 완료 주장, 모델 형식 오류, 인증·네트워크·시간·예산 실패, 취소, 악성 도구 요청, 비밀값·링크·제어 문자, 재조회와 부분 사용량 보존을 확인했다. 이 시험은 외부 API 요금이나 라이브 EKS 상태를 확인하지 않는다.
