예를 들어 `case-05`는 연결 풀 획득 대기 830ms와 SQL 실행 12ms를 구분했고, `case-07·08`은 새 revision의 실패와 롤백 뒤 복구 관측을 구분했다. 정상 `case-09·10·13·14`에서는 인용된 관측 사실은 지지되더라도 진단 상태를 과도하게 유보할 수 있다. 첫 반복에서 도구 탐색 AI의 네 건, 수정 고정 증거 AI의 `case-14`가 그 예이며 **의미 검토의 통과가 진단 상태 일치를 뜻하지 않는다**. 원본 문장이 원인 단서를 직접 적은 합성 자료라는 점도 이 예비 Top-1 비율을 쉽게 만들 수 있다.

사건별 판단 근거는 개인 저장소의 `a7-v3-fixed-self-review.json`, `a7-v3-ai-self-review.json`에 기록했고, 채점기를 적용한 `a7-v3-fixed-self-score.json`, `a7-v3-ai-self-score.json`에는 `non_independent_preliminary` 표기를 남겼다. 채점기에는 두 방식 모두 첫 반복 **16/48회 검토 진행**, 예비 Top-1 8/8로 표시되지만, 전체 48회 의미 정확도·금지 주장 합계는 여전히 **수동 검토 대기**다. 독립 검토자는 별도 빈 판정표로 같은 원본을 다시 판단해야 한다. 결과가 달라지면 차이를 기록하고 완료 기준을 재판정한다.

## 남은 작업과 판정 기준

1. 두 방식의 v1 개발 반복과 v2 결과를 보존하고, 수정 고정 증거와 도구 탐색 방식의 v3 새 미노출 입력 평가를 각각 48/48회 완료했다. 원래 v2 고정 증거의 남은 4회는 실패 이력으로 보존하며 수정 버전의 성공으로 소급하지 않는다. v3는 평가자 블라인드 자료가 아니며 `partial`·`failed` 시도는 성공한 AI 진단으로 채점하지 않는다.
2. 수동 분석 비교군과 검토 표를 준비한다. 고정 증거 AI 요약 코드는 [`fixed_summary.py`](../src/ai_ops/fixed_summary.py)에 구현해 전체 반복·저장 재조회를 확인했다. 규칙·고정 증거 AI는 전체 검증 묶음, 도구 탐색 AI는 실제 조회한 항목과 런북만 보므로 이 정보 범위 차이를 결과에 명시한다.
3. 별도 수동 검토에서 Top-1 원인·근거 문장의 의미상 지지·금지 주장을 채점한다. 채점기는 완료된 실행마다 검토 항목을 내보내며 `--review`로 받은 사람의 판단만 합산한다. 첫 실행 장애 8건이 모두 검토되기 전에는 Top-1 비율을, 전체 실행이 완료·검토되기 전에는 근거 의미 정확도를 확정하지 않는다. 자동 `evidence_id` 존재 검사 100%만으로 근거 정확도 100%라고 쓰지 않는다.
4. 첫 실행 기준 Top-1 7/8 이상, 정상 오탐 0/6, 판단 유보 2/2, S10 복구 구분 2/2를 확인하고 반복 변동·시간·비용·오답 사례를 함께 공개한다. 미달이면 개선 작업을 등록하고 A 완료로 표시하지 않는다.
5. v1은 임시 깨끗한 체크아웃의 잠금 의존성 설치·로컬 시험과 rules/AI 결과 재조회를 확인했다. AI 전용 원격 CI는 `caeba63`에서, 기존 앱 호환성 CI의 브랜치 push는 `5233c30`에서 통과했다. v3의 독립 의미 판정과 기존 앱 CI의 PR 이벤트·경로별 트리거·실패 전파 확인은 남아 있다. A5의 HolmesGPT 동등 조건 비교도 별도 미완료다.

## 로컬 재현

고정 자료 검증과 규칙 비교군은 외부 모델 호출이 없다. `AI_OPS_PYTHON`에는 Python 3.11 이상과 잠금 버전의 Pydantic 2.13.5가 설치된 실행 파일을 지정한다. 실행 저장소는 프로젝트 밖의 개인 경로를 사용한다.

```sh
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/build_holdout_fixtures.py --check
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/run_holdout.py --mode rules --store "$AI_OPS_EVAL_STORE"
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/score_holdout.py --runs "$AI_OPS_EVAL_STORE/a7-rules-results.json"
```

새 v2 입력은 다음처럼 별도 suite·정답표를 지정한다. 유료 반복을 이어 실행할 때 `--store`는 기존 사건·예산 장부가 있는 **같은 개인 저장소**여야 한다. `--repeats 3`으로 재실행하면 완료된 조합은 건너뛰며, 일일 상한에 도달하면 중지한다.

```sh
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/build_holdout_v2_fixtures.py --check
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/run_holdout.py \
  --suite ai-ops/evals/fixtures/holdout-v2/suite.json --mode ai --repeats 3 \
  --store "$AI_OPS_EVAL_STORE"
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/score_holdout.py \
  --suite ai-ops/evals/fixtures/holdout-v2/suite.json \
  --rubric ai-ops/evals/rubrics/holdout-v2/scenarios.json \
  --runs "$AI_OPS_EVAL_STORE/a7-v2-ai-a5-context-v2-results.json"
```

현재 v3 결과를 확인할 때는 기존 v2 대신 아래 suite·정답표와 결과 파일을 사용한다. 완료된 결과의 재채점은 모델을 호출하지 않는다. 새 평가를 실행하면 유료 API 호출이 발생하므로 현재 선예약액과 UTC 일일 한도를 먼저 확인한다.

```sh
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/build_holdout_v3_fixtures.py --check
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/score_holdout.py \
  --suite ai-ops/evals/fixtures/holdout-v3/suite.json \
  --rubric ai-ops/evals/rubrics/holdout-v3/scenarios.json \
  --runs "$AI_OPS_EVAL_STORE/a7-v3-fixed-prompt-v2-results.json"
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/score_holdout.py \
  --suite ai-ops/evals/fixtures/holdout-v3/suite.json \
  --rubric ai-ops/evals/rubrics/holdout-v3/scenarios.json \
  --runs "$AI_OPS_EVAL_STORE/a7-v3-ai-a5-context-v2-results.json"
```

첫 반복의 수동 검토 자료를 다시 만들려면 다음을 사용한다. 아래는 v2 도구 탐색 결과의 예시이며, v3 검토에는 `--suite`·`--rubric`·`--runs`·출력 이름을 v3로 바꾼다. 고정 증거 방식에는 결과 파일과 출력 이름의 `ai`를 `fixed`로 바꾼다. 출력은 프로젝트 밖 개인 저장소에만 두며, 생성 직후 판정표의 값은 모두 비어 있다.

```sh
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/export_holdout_review.py \
  --suite ai-ops/evals/fixtures/holdout-v2/suite.json \
  --rubric ai-ops/evals/rubrics/holdout-v2/scenarios.json \
  --runs "$AI_OPS_EVAL_STORE/a7-v2-ai-a5-context-v2-results.json" \
  --packet "$AI_OPS_EVAL_STORE/a7-v2-ai-review-packet.json" \
  --template "$AI_OPS_EVAL_STORE/a7-v2-ai-review-template.json" --first-only
```

실제 AI 도구 탐색 평가는 같은 실행기를 `--mode ai --repeats 3`으로, 수정 고정 증거 AI 요약은 `--mode fixed --repeats 3`으로 사용한다. 두 모드는 개인 저장소의 API 키를 읽고 유료 호출하므로 수동으로 실행한다. 평가 실행기의 기본 UTC 일일 상한은 $10, 건당 상한은 $0.10이다. 2026-10-03 추가 실행에는 `--daily-budget-usd 30`을 명시했고 실행기는 $30을 넘는 옵션을 거부한다. v2 suite에서 수정 고정 증거의 기본 결과 파일은 `a7-v2-fixed-prompt-v2-results.json`이다. 원래 버전의 `a7-v2-fixed-results.json`은 별도로 보존한다. 도구 탐색 새 기본 결과 파일은 `a7-ai-a5-context-v2-results.json`, 기존 버전은 `a7-ai-results.json`이다. 예산 장부와 사건 기록은 기존 개인 저장소를 그대로 사용해야 일일 제한이 유지된다. 같은 설정으로 먼저 1회 실행한 결과 파일의 반복 목표는 `--repeats 3`으로 올려 완료한 실행을 건너뛰고 이어갈 수 있다. 개발 평가가 끝나면 A7 전용 상한을 다시 검토한다. 채점 JSON의 `manual_review` 항목에는 원인 후보·사실·정답 기준과 비어 있는 검토 필드가 들어 있다. 사람이 해당 필드를 확인하기 전에는 Top-1과 의미상 근거 정확도를 확정하지 않는다.

특정 사건만 순서대로 이어서 검사할 때는 `--case case-05`처럼 지정한다. 여러 사건이면 `--case`를 여러 번 쓴다. 이 옵션은 이번 호출에서 실행할 사건만 고르며 저장된 suite·모델 설정을 바꾸지 않는다. 기존 실패 사건에 다시 비용을 쓰기 전에는 실패 원인을 먼저 확인한다.

검토 결과는 저장소 밖의 JSON 파일에 보관한다. `mode`는 해당 실행의 `rules`·`fixed`·`ai` 중 하나여야 한다. 완료된 각 `(case_id, repeat)`에 대해 `top1_correct`는 장애만 참/거짓으로 적고 정상·정보 부족은 `null`로 적는다. 인용 문장이 실제 증거에 의해 지지되는지와 금지 주장이 있는지 역시 원본을 읽고 판단한다. `note`에는 판정 근거를 기록한다. 일부만 검토해도 진행률은 나오지만 점수는 필요한 대상이 모두 검토될 때까지 대기 상태다.

```json
{
  "schema_version": 1,
  "suite_hash": "83c5ff59a4014ceaa98cda3260752544d7d371b2a01d0f8c1d2418e47913de24",
  "mode": "rules",
  "reviews": [
    {
      "case_id": "case-01", "repeat": 1,
      "top1_correct": false,
      "evidence_semantically_supported": true,
      "forbidden_claim_present": false,
      "reviewer": "검토자 이름",
      "note": "보고서의 원인 후보와 ev-h01-1·ev-h01-2 원문을 대조한 이유"
    }
  ]
}
```

```sh
PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/score_holdout.py \
  --runs "$AI_OPS_EVAL_STORE/a7-rules-results.json" \
  --review "$AI_OPS_EVAL_STORE/a7-rules-review.json" \
  --output "$AI_OPS_EVAL_STORE/a7-rules-score.json"
```
