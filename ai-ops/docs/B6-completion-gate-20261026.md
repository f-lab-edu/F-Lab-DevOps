## 범위와 해석

- S10 하위 사례의 **자동 조사와 모델 보고서 생성**은 확인했다. 기존 CI가 원복했으며 AI가 클러스터를 복구한 것은 아니다. 보고서는 사용자 요청 경로의 복구 또는 현재 전체 서비스 정상 여부를 검증하지 않았다.
- 사용자는 Claude를 통한 독립 의미 평가를 이번에 생략했다. E1은 독립 비교를 후속 확장으로 분류하므로 이것만으로 B-06을 보류하지 않는다. 단, 자체 평가의 범위는 명시하고 `needs_review`를 승인 완료로 바꾸지 않는다.
- 2026-10-21 규칙 전용 운영 데모의 외부 호출 0회, 2026-10-26 상시 경로 모델 실습의 추정 $0.0083285·예약 $0.10, 별도 로컬 정상 S2 집계 비교의 추정 $0.009861·예약 $0.10, 첫 v3 실패의 추정 $0.009591·예약 $0.10, 새 v3 진단 비교의 추정 $0.0048968·예약 $0.10을 구분한다. 로컬 세 건의 UTC 당일 예약은 합계 $0.30이며 클러스터 캠페인 장부와 별개다. 예약액과 사용량 추정액은 실제 청구액이 아니다. 정확도·오탐률·MTTR 개선 수치는 산출하지 않는다.
- S1~S11 전면 재실행은 요구하지 않는다. [운영 평가표](B6-operational-evaluation.md#s1s11-대조)의 당시/최신 상태와 미검증 이유를 유지한다. 작업 목록의 S9/S11 완료 표시도 해당 실측 근거와 현재 평가표를 대조하기 전까지 이 판정의 완료 근거로 사용하지 않는다.

## 완료까지의 최소 순서

1. [의미 평가 기준](B6-model-semantic-criteria-20261026.md)에 **정상 관측·제한 장애·자료 부족** 세 부류의 필수 설명과 금지 주장을 고정했다. 새 실습의 순서 증거를 수집·정제해 [새 v3 일회 비교](B6-normal-sequence-diagnostic-live-result.md)의 제한된 정상 설명까지 자체 평가했다. 다음은 이 로컬 결과와 별도로, **배포된 자동 조사 경로**가 정상 사례의 순서 근거를 안전하게 접수·설명하는지 설계·검증하는 일이다. 새 모델 호출에는 새 입력·비용·기간의 별도 승인이 필요하다.
2. 기존 모의 시험을 재사용해 배포된 실습 경로의 중단 전후·동일 CI 재접수·예산 거부·만료 시 새 전송 차단과 정리 절차를 최소 범위로 확인한다. 새 유료 호출을 반복해 429나 예산 초과를 만들지 않는다.
3. 평가표 JSON과 데모 문서에서 날짜가 지난 “미배포/미검증” 문장을 당시 기록으로 표시하고, 근거 링크와 미검증 사유를 최신 판정에 연결한다. 위 필수 조건을 충족한 뒤 B단계 전체의 B-01~B-05 미결 항목까지 확인해 C 진입을 **별도로** 판단한다.

C 진입을 허용하더라도 그것만으로 실행 권한이나 복구안 승인이 부여되지 않는다. C의 첫 범위는 격리 실습 앱의 이전 정상 이미지로 되돌리는 승인 기반 GitOps 변경이다.

## 순서 수집 후속

[실제 GET·같은 Pod 로그 수집](B6-normal-sequence-capture.md)을 한 건 검증해 miss→hit 두 쌍·원복·잠금 해제를 확인했다. 이제 남은 첫 연결은 **수집기 내부 원본 snapshot과 새 조회 기록을 결합한 v3 exporter**다. v3 모델 보고서와 상시 경로 검증은 아직 없으므로 위 의미 조건·전체 완료 보류 판정을 유지한다.

이후 [v3 exporter](B6-normal-sequence-exporter.md)의 실제 반출까지 확인했다. 다음 첫 연결은 **v3용 비공개 일회 비교 저장소·미리보기·승인·예산**이다. 실제 모델 전송·적극적 정상 설명·상시 경로 검증은 아직 없으므로 완료 보류는 유지한다.

[v3 일회 비교 준비](B6-normal-sequence-comparison-preparation.md)에서 위 저장소·승인·공유 예산과 실제 입력의 전체 미리보기를 구현했다. 현재는 사용자 승인 전 `prepared`이며 다음은 승인된 한 건의 모델 보고서와 사전 의미 기준 대조다. 상시 경로 검증과 완료 보류는 유지한다.

이후 사용자 승인된 [v3 실제 전송](B6-normal-sequence-live-failure.md)은 계약 검사 실패로 끝났다. 초안·세부 사유가 없어 의미 평가는 미실시이며 적극적 정상 설명 조건은 여전히 미충족이다. 다음 우선 작업은 **추가 모델 호출 전 진단 보존·고정 실패 사유 분류의 구현과 모의 검증**이다. 전체 완료·C 진입 보류를 유지한다.

[진단 보존 후속](B6-sequence-failure-diagnostics.md)에서 위 우선 작업을 새 비교 버전으로 구현하고 모의 계약 위반으로 검증했다. 기존 실패의 상세 사유는 복구할 수 없다. 새 모델 비교가 필요하면 새 미리보기와 입력별 승인을 준비해야 하며, 적극적 정상 설명·상시 경로·전체 완료 판정은 계속 보류한다.

이후 승인된 [새 v3 비교](B6-normal-sequence-diagnostic-live-result.md)는 같은 아이템의 miss→hit 두 쌍을 **제한된 정상 캐시 동작**으로 설명해 S2 하위 사례의 적극적 설명 기준을 자체 평가에서 충족했다. 정형 계약도 통과했지만 `needs_review`를 유지한다. 배포된 상시 정상 사례 경로와 실패 경계 검증은 남아 있으므로 B-06 전체 완료·C 진입 보류는 바뀌지 않는다.

[상시 v3 gateway 후속](B6-normal-sequence-continuous-gateway.md)에서 순서 입력의 서명 계약·정책 선택·대기열 연결을 구현했다. 사용자는 정상 관측의 시작점을 **격리 실습 CI**로 선택했다. 현재 구현과 검증 범위는 gateway의 로컬 모의 경로이며, 정상 관측 CI·출처 검증·worker 연결과 실제 배포는 남아 있다. 이 단계에서 새 외부 모델 호출은 하지 않았다.

이후 [정상 관측 CI 실행자·권한](B6-normal-ci-executor.md)의 workflow·OIDC·현재 Pod 제한 RBAC와 수집기 내부 원본 대조·정제·원복 영수증을 구현했다. 실행자 코드의 모의 시험과 실제 클러스터의 읽기 전용 대상 고정 계획을 배포·실습 완료와 구분한다. 실제 활성화·정상 CI 출처 검증·worker 연결·영구 source 보관/재시작 경계 및 모델 실측은 계속 남아 있다.
