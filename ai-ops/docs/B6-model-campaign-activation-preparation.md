# B-06-M7-3 실습 모델 캠페인 활성화 사전 준비

상태: **2026-10-24 KST 로컬 코드·합성 시험 준비**. 현재 프로젝트 AWS 인프라가 정리되어 실제 클러스터 대상·Secret·캠페인 승인을 만들거나 모델을 호출하지 않았다. [M7-2 비활성 배포 준비](B6-model-campaign-deployment-preparation.md)의 후속이며, 이 문서 자체는 활성화 승인이 아니다.

## 이번에 준비한 기능

1. `model_campaign_review.py`는 **prepared** 상태의 캠페인 결합 해시, 구현 해시, 실습 대상, 이미지 digest, 정제 샘플 해시, API 키 지문, 호출 계획, 24시간·10건·건당 $0.10·UTC 일일 $1 한도를 검증한다. 가격 확인일은 캠페인 시계 기준 최대 7일 이내여야 한다. 두 전송 요청의 해시·크기와 정제 샘플을 검토 자료에 담는다. `activation_allowed=false`와 미래 입력 자동 전송 범위를 명시한다. 실제 캠페인이 없으므로 이번에는 합성 자료로만 시험했다.
2. 로컬 자격 파일 검사는 현재 사용자 소유·단일 링크·일반 파일·타 사용자 접근 불가·허용 문자/길이를 확인한 뒤 **SHA-256 지문만** 반환한다. API 키와 worker↔gateway 토큰 원문은 검토 자료에 넣지 않는다. 키 파일·검토 자료는 Git에 추가하지 않는다.
3. gateway의 두 HTTP 요청 각각 직전에 캠페인의 승인 상태와 만료를 다시 확인한다. 토큰 계산이 끝난 뒤 중지하면 생성 요청은 시작하지 않고 `campaign_stopped`로 남긴다. 요청이 이미 시작된 뒤의 응답까지 취소한다는 보장은 없다. 전송 상태가 불명인 항목은 자동 재시도하지 않는다.

## 재설치 후 실제 활성화 전에 할 일

1. 최신 main과 이미지로 실습 리소스를 비활성 설치한다. 새 EKS 내부 API 주소, `lab-api` Deployment UID, `ci-config` 해시, 클러스터 CA 지문, 이미지 digest를 다시 조회한다. 이전 설치의 UID·주소·digest는 재사용하지 않는다. gateway/proxy 0/0, `AI_MODEL_ENABLED=false`, worker bridge 꺼짐과 Secret 부재를 확인한다.
2. API 키는 `ai-model/model-openai-key`로 gateway에만, 별도 랜덤 client 토큰은 `ai-model/model-client-auth`와 `ai-ci/model-client-auth`에 동일 값으로 배포한다. 로컬 입력 파일은 소유자 전용으로 관리하고 Secret 값이나 `--from-literal` 문자열을 명령 기록·출력·Git에 남기지 않는다. 배포 직후 파일 지문과 마운트 자격의 일치를 확인한다. 권한과 NetworkPolicy는 이전 M6/M7-2 경계를 유지한다.
3. 실제 클러스터 범위로 새 **prepared** 캠페인을 만들고, 정제된 샘플 view와 두 요청의 해시·크기, 대상·이미지·코드·자격 지문, 가격 출처/확인일, 미래 자동 입력, 기간/건수/비용 상한을 한 검토 자료로 제시한다. API 가격과 계정의 선택적 데이터 공유 해제 및 제공자 보관 조건을 그 시점에 다시 확인한다. 검토 자료는 개인 저장소에만 둔다.
4. 사용자에게 **이 특정 캠페인의 범위와 미래 자동 입력을 포함한 명시 승인**을 받은 뒤 `approve_live`로 정확한 결합 해시를 승인한다. 그다음 Secret/PVC·실시간 상태를 재검증하고 활성 패치를 작성·적용한다. worker 연결은 gateway 준비 후 연다. 승인 전 gateway/proxy 복제수를 올리거나 worker bridge를 켜지 않는다.
5. 첫 정제 입력 한 건의 장부 예약·토큰 계산·생성·`needs_review` 보고서를 검증한다. 보고서 의미는 사람이 별도 검토한다. 한도 초과·대상 변경·권한 실패·중지 후 두 번째 호출 차단을 제한적으로 검증한다. B-06 전체 완료는 별도 평가다.

## 중지·복구

추가 접수를 막으려면 worker bridge를 끄고 장부의 캠페인을 `stopped`로 바꾼 뒤 gateway/proxy를 0으로 내린다. 필요하면 두 자격을 폐기한다. 이미 시작된 HTTP 요청은 끝날 수 있으므로 예산 예약과 `sending` 기록을 확인한다. 결과를 모르는 전송을 새 캠페인에 자동 재등록하지 않는다. 재설치 후에는 새 대상·키·이미지로 처음부터 검토하고 승인한다.

다음 작업은 실제 설치가 이뤄진 뒤 현재 클러스터를 기준으로 검토 자료와 비활성 배포를 검증하는 것이다. 권장 추론 깊이는 **GPT-6 SOL high**다.
