# B-06-M7 실습 모델 캠페인 사전 점검

상태: **2026-10-24 KST 사전 점검과 M7-1 로컬 전송·장부 계약 구현, 실제 캠페인 승인·활성화 전**. 이 문서는 승인 요청 자체가 아니며, 키를 클러스터에 넣거나 네트워크 권한을 열거나 모델 API를 호출하지 않았다. [M6 비활성 배포](B6-model-service-deployment.md)의 다음 작업을 구체화한다.

## M7-1 로컬 구현 결과

`ContinuousCIBridge`가 규칙 보고서 저장 후 만든 `Projection`을 worker의 `ModelGatewayClient`가 `ModelSubmission`으로 바꾼다. 내부 gateway에는 정제 `ModelView`, 출처 결합 해시, 규칙 보고서 참조만 보내며 원본 snapshot·로그·이벤트·증거 ID 대응표·CI artifact는 보내지 않는다. gateway는 고정 서비스 자격과 HMAC 서명, 정규 JSON, 크기·필드·view 해시, 캠페인 ID를 검사한 뒤 독립 SQLite 장부에 중복 없이 기록한다. 조회·정제 실패 기록도 동일한 내부 서비스 경계로 처리한다. worker의 기본 설정은 모델 연결 꺼짐이며 모델 경로 실패가 저장된 규칙 보고서를 바꾸지 않는다.

장부에는 `prepare_live_campaign`과 `approve_live`, `process_live`를 추가했다. 승인 범위는 대상 UID·설정/클러스터 해시·이미지 digest·샘플 view 해시·정책·프롬프트·코드 해시·모델/가격/목적지·키 지문·기간/예산에 묶인다. 실제 전송은 이 해시와 별도 승인, 선택적 공유 해제 및 제공자 보관 인지, 이미지·키 일치, 가격 유효성을 확인한 뒤 UTC 일일 예약액을 먼저 확정해야 한다. 단회 전송 후 결과는 별도 보류 보고서로 남기고 자동 재전송하지 않는다. 이 경로는 **모의 응답과 로컬 HTTP 서버로만** 시험했다. 현재 배포 gateway는 여전히 `AI_MODEL_ENABLED=false`, 복제수 0이며 활성 장부/처리 루프가 없다.

다음 M7-2에서는 실제 배포에 필요한 gateway 장부/처리 루프와 worker 주입 환경, 전용 Secret 회전, 한 방향 네트워크 정책, 이미지 digest/현재 UID 재확인, 설치·정리 수명주기를 함께 검증한다. 그 결과와 새 입력 예시를 포함한 완성 검토안에서만 사용자에게 캠페인 승인을 요청한다. 승인 전 모델 API 호출은 계속 0회다.

## 첫 캠페인 검토 범위

첫 입력은 `ai-ci` worker가 이미 **규칙 보고서를 저장한** `ai-ops-lab/lab-api`의 CI 조사 한 건이다. 그 snapshot에서 [M1 정제 정책](B6-model-data-policy.md)의 `ModelView`만 선별한다. Pod 실명은 별칭으로 바꾸고 상태·재시작 수, 캐시/DB 설정 여부, 등록된 집계 지표와 출처 상태만 보낸다. 로그·이벤트·배포 원문, 사용자 입력, URL/item ID, 원본 증거 ID 대응표, Secret, CI artifact는 보내지 않는다. 제외·누락 상태는 정제 입력에 남기며 0 또는 정상으로 바꾸지 않는다. 앞으로 접수될 입력의 실제 내용은 지금 알 수 없다.

제안 모델은 `gpt-6-sol`의 `low` 추론, 목적지는 `https://api.openai.com:443`이다. 요청은 토큰 계산 최대 1회와 생성 최대 1회로 제한하고 `store=false`, `background=false`, `service_tier=default`, 출력 최대 1,024토큰, 입력 요청 최대 32,000바이트, HTTP 각 30초·전체 60초를 유지한다. 캠페인 기간은 최대 24시간, 생성 최대 10건, 건당 **$0.10 예약**, UTC 하루 **$1 예약**이다. 최대 10건이라는 수치는 실행 약속이 아니며 정상 관측 1건과 제한된 장애 관측 1건만 우선 검토한다. 별도 로컬 M3 실제 호출 장부와 클러스터 장부를 합산하지 못하므로 첫 캠페인 동안 같은 API 계정의 로컬 live 비교 실행은 중지하거나 공통 예산 장부를 마련해야 한다. 예약액은 실제 청구액이 아니다.

2026-10-24 [OpenAI Docs 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-sol)에서 표준 텍스트 100만 토큰당 입력 $2, 캐시 읽기 $0.20, 캐시 쓰기 $2.50, 출력 $10을 확인했다. 이 가격·계정의 선택적 데이터 공유 설정은 활성화 직전에 다시 확인한다. `store=false`여도 [OpenAI Docs 데이터 제어](https://developers.openai.com/api/docs/guides/your-data)에 따른 기본 악용 감시 로그에 고객 내용이 포함되고 통상 최대 30일 보관될 수 있다. 이 조건에 대한 인지는 별도 캠페인 승인에 포함한다.

## 활성화 전에 구현·검증할 것

1. `continuous_model.py`의 **mock 전용 계획·처리**와 gateway의 **항상 503**을 실제 캠페인 승인·예산 예약·단회 전송 경로로 확장한다. 승인 해시는 대상 UID/클러스터 지문/설정·정책·프롬프트·구현/모델·가격/목적지/키 지문/기간·건수·금액과 샘플 view에 결합한다. 원본이나 대응표는 gateway로 보내지 않는다.
2. worker가 규칙 보고서 저장 후 정제 view만 내부 gateway에 제출하도록 연결한다. 별도 서비스 자격, 크기·정형 계약, 중복 키, `ai-ci`→`ai-model` 한 방향 NetworkPolicy를 검증한다. 규칙 보고서/알림은 모델 실패나 지연의 영향을 받지 않아야 한다.
3. 전용 API 키와 worker↔gateway 자격을 검토된 경로로 생성·회전하고, gateway 장부 PVC에만 예산·중복 상태를 저장한다. Secret 값은 Git·CI artifact·미리보기·로그에 남기지 않는다. 키가 없는 지금은 배포 복제수를 올리지 않는다.
4. 토큰 계산 전부터 UTC 일일 예약을 원자적으로 기록하고 중복/재시작/응답 유실을 **자동 재전송하지 않게** 검증한다. 가격 확인이 7일을 넘거나 UID·설정·정책·이미지·키 지문·목적지가 바뀌면 중지한다. 본문 7일·본문 없는 장부 90일 정리와 중지 후 새 요청 차단도 시험한다.
5. 위 코드의 모의 실패·중단·권한 시험과 새 이미지 검증을 마친 후, **완성된 캠페인 검토안**에서 미래 입력이 자동 전송된다는 점·범위·비용·제공자 보관을 명시해 사용자의 별도 승인을 받는다. 승인 전에는 `ai-model` 0/0과 API 호출 0회를 유지한다.
6. 승인된 실습에서 정상 관측 1건과 제한된 장애 관측 1건을 실행한다. 동일 view의 규칙/모델 보고서, 인용 근거, 누락·오진, `partial/unknown`, 제안 조치의 `not_executed`를 사람과 대조한다. 실패·한도·중지·정리 결과를 기록한 뒤 B 종료/C 진입을 따로 판정한다. 두 사례만으로 일반 정확도나 MTTR 개선을 주장하지 않는다.

**현재 중단 조건:** M7-1 코드는 로컬에서만 검증했고 gateway는 배포상 0/0이며 실행 진입점은 계속 비활성이다. 실제 장부/처리 루프, worker 환경 주입, 전용 Secret, worker egress, 새 캠페인 승인이 없다. 따라서 지금 복제수를 1로 변경하거나 이전 M3 승인을 복사해도 실제 캠페인은 시작할 수 없다. 다음 구현 작업은 **M7-2 배포 연결과 비활성 상태의 설치·복구 검증**이며 권장 추론 깊이는 **GPT-6 SOL high**다.
