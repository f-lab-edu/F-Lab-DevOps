# B-06-M3 실제 입력 준비와 제한 모델 비교

상태: **2026-10-23 KST 승인한 실제 정제 입력 한 건의 모델 비교·자체 내용 검토 완료**. 토큰 계산 1회·보고서 생성 1회를 실행했다. 아래 준비 기록과 실제 실행 결과를 구분한다. [M1 정책](B6-model-data-policy.md)과 [M2 모의 검증](B6-model-projection-implementation.md)의 후속이며 B 전체 완료·C 진입은 보류한다.

## 이번 작업의 목적과 처리 흐름

실습 서버에서 실제 수집한 자료 중 허용 필드만 골라 OpenAI에 한 번 보내고, 같은 자료를 받은 규칙 분석과 모델 보고서를 비교한다. 모델에게 클러스터 조회·변경 도구를 주지 않는다. 기존 worker의 모델 비활성·production 자료 차단·기존 보고서는 유지한다.

실습 읽기 조사 → 원본 snapshot 고정 → 상태·설정 여부·집계 지표 선별/별칭 처리 → 전체 전송 미리보기 → 해당 입력 한 건 승인 → 토큰 계산/비용 검사 → 모델 생성 한 번 → 계약 검사 → 같은 입력의 규칙 결과와 내용 검토 순서다. **이 입력 한 건은 내용 검토까지 수행했다.** 새 장애는 주입하지 않았다.

## 전송·비용·보관 조건

`store=false`, `background=false`, `service_tier=default`, 최대 출력 1,024토큰, HTTP 각 30초/전체 60초다. 건당 $0.10·UTC 일일 $1의 별도 실사용 예약 장부를 사용한다. A7 개발 한도 $30을 상속하지 않는다. 이번 실제 실행에서 $0.10을 예약했다. 이는 실제 사용량 기준 추정액이나 청구 확정액과 다르다.

2026-10-23 [모델 문서](https://developers.openai.com/api/docs/models/gpt-6-sol)와 [가격 문서](https://developers.openai.com/api/docs/pricing)를 확인했다. 100만 토큰당 입력 $2·출력 $10·캐시 쓰기 $2.50·캐시 읽기 $0.20을 계획에 고정했다. 토큰 계산 후 보수적인 비용 상한을 검사하며, 실제 사용량이 없거나 요청이 실패한 것을 비용 0으로 단정하지 않는다.

`store=false`는 모든 제공자 보관을 없애는 옵션이 아니다. 기본 악용 감시 자료는 최대 30일 보관될 수 있고 예외가 있으며, 별도 승인된 Zero Data Retention 계정으로 가정하지 않는다. API 계정의 선택적 데이터 공유는 코드에서 확인할 수 없으므로 운영자가 꺼짐을 확인해야 한다. [OpenAI 데이터 정책](https://developers.openai.com/api/docs/guides/your-data)

로컬 입력·대응표·승인·보고서·미리보기는 7일, 본문 없는 예산 장부는 90일 정리 대상으로 구현했다. 자동 스케줄러가 실행 중이라는 뜻은 아니며 `purge --apply`가 필요하다. 준비 내용이나 코드가 바뀌면 새 미리보기·승인이 필요하다. 기존 mock 승인을 live 전송에 사용할 수 없다.

## 검증과 아직 남은 것

현재 작업 브랜치에서 전체 **380개 시험**(기존 373개와 새 전송 경계 7개), 문법·기존 배포 정적 검사가 통과했다. 기존 SQLite ResourceWarning이 로그 검사에 섞이는 문제를 피하는 경고 필터를 사용했다. M2 당시 최신 main 기준 398개와는 브랜치가 달라 숫자를 합산하거나 최신 main 전체 통과로 표현하지 않는다.

실제 exporter 호환성·소유 UID 검증·정제 입력 생성에 성공했다. 전후 운영 앱·AI StatefulSet/PVC·실습 앱/수집기 UID와 generation이 같았다. 클러스터의 코드·이미지·권한·연결 설정은 바꾸지 않았다. 모의 HTTP 시험의 통과는 실제 제공자 API 호환성·모델 품질·실제 청구 검증을 의미하지 않는다.

준비 시점에는 입력별 승인과 계정 공유 설정 확인을 기다렸다. 이후 아래 사용자 확인을 근거로 실행했다. 오류나 불명확한 결과를 자동 재전송하지 않는다. 이 한 사례로 일반 정확도·MTTR 개선·전체 정상 진단을 주장하지 않는다. 작업 검토의 권장 깊이 GPT-6 SOL high와 실제 호출 모델의 low를 구분한다.

이번 검토는 구현한 동일 에이전트의 **자체 내용 검토**다. 독립 평가자 판정이나 블라인드 정확도 측정이 아니다. partial/unknown·조치 미실행은 프롬프트와 스키마에서 강제한 계약이므로 모델이 독립적으로 현재 상태를 판정했다고 주장하지 않는다. 코드상 결과는 `needs_review / semantic_review_required`로 보존한다. 이는 API 실패가 아니라 생성 후 내용 검토를 요구하는 상태이며, 검토 결론은 본 문서/검증 자료에 별도로 기록한다. 재실행해 이 상태를 지우지 않는다.

실행 후 클러스터 내부의 같은 원본을 다시 정제해 저장된 projection 전체와 일치함을 확인했다. 운영 앱·AI StatefulSet/PVC·실습 앱/수집기 UID/generation도 보존됐다. 키·입력·전체 모델 보고서·원본 대응표는 비공개 로컬 저장소에 남긴다. 이번 사례는 **실제 수집 자료의 제한된 외부 분석 연결**을 입증하며, 장애 원인 진단 능력·정상 판별·자동 해결·상시 worker 모델 활성화를 입증하지 않는다.
