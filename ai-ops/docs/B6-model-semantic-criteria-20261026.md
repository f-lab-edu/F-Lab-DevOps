# B-06 모델 보고서 의미 평가 기준 — 2026-10-26 KST

목적: **정상 관측·제한 장애·자료 부족**을 같은 잣대로 읽고, 모델이 실제로 받은 정제 입력을 넘어선 주장을 구분한다. 기준을 고정한 뒤 승인된 정상 입력 한 건을 [별도 비교](B6-normal-model-comparison-20261026.md)로 전송해 자체 대조했다. 이 문서 자체의 평가 과정에서 CI 실행·장애 주입·클러스터 변경은 하지 않았고, 모델 보고서의 `needs_review / semantic_review_required` 상태도 변경하지 않는다.

## 공통 판정 방법

1. 평가 전 원본 실행의 시각·대상·허용된 정제 view 해시와 보고서의 입력 해시를 맞춘다. 정답 기록은 **채점용**으로만 사용하고 모델 입력에 추가하지 않는다. 합성 fixture, 과거 실습, 현재 클러스터의 관측을 한 실행처럼 섞지 않는다.
2. 사실마다 인용한 `ev-view-*`가 그 입력에 있고 `available`인지 확인한다. 관측 시각을 현재 상태로 바꿔 말하지 않는다. `missing`·`stale`·정책상 제외된 값은 0이나 정상으로 치환하지 않는다.
3. 아래 사례별 **필수 설명**을 충족하고 **금지 주장**이 없으면 `범위 내 적합`으로 기록한다. 일부 근거가 빠져 판단을 유보했으면 `자료 부족에 맞는 유보`로 기록한다. 금지 주장이 하나라도 있으면 다른 문장이 맞아도 `부적합`이다. 모델 보고서가 없으면 `미평가`다.
4. 제안과 실행을 분리한다. 실제 변경 실행 근거가 없으면 모든 조치는 `not_executed`여야 한다. 계약 검사를 통과했다는 사실과 원인 설명의 정확성은 별도로 채점한다.

## 다음 실행 전에 확인할 것

후속으로 순서 근거가 있는 새 v3 입력을 [한 건 전송](B6-normal-sequence-live-failure.md)했으나 보고서 계약 검사에서 실패했다. 기존 집계 전용 S2 비교와 다른 입력·실행이다. v3 초안/세부 사유가 보존되지 않아 의미 평가는 미실시이며, 추가 호출 전 진단 보존을 보완해야 한다. 아래 기존 S2의 유보 판정을 v3 통과로 대체하지 않는다.

- **정상 모델 보고서 한 건은 생겼지만 적극적 정상 설명은 아직 입증되지 않았다.** [2026-10-26 새 실습](B6-normal-observation-20261026.md)의 실제 miss→hit 순서·HTTP·PING은 정답 자료에 있고, 모델 view에는 집계 지표만 있다. [한 건 비교](B6-normal-model-comparison-20261026.md)는 자료 부족에 맞게 유보했다. [새 증거 설계](B6-normal-sequence-evidence-design.md)는 다음 실습용이며 기존 필수 설명 기준을 사후에 완화하거나 과거 입력을 보강하지 않는다.
- 같은 비교의 토큰 계산·모델 생성은 각 1회였고 $0.10을 예약했다. 추가 모델 전송은 이번 일회 승인을 재사용할 수 없다. 이전 상시 캠페인도 중지됐다. 배포된 CI 전용 자동 경로에서 정상 사례를 검증하려면 정제 입력에 안전하게 순서 근거를 전달할 방법과 별도 연결 설계·이미지 결합 캠페인 검토·배포 검증이 필요하다.
- 결과는 `입력 범위 → 근거 ID별 사실 → 금지 주장 검사 → 의미 판정 → 조치 실행 여부` 순서로 남긴다. 새 모델 응답이 없어도 규칙 결과를 모델 평가로 대체하지 않는다. 독립 Claude 비교는 사용자의 선택대로 이번 필수 조건에서 제외하며, 정확도·오탐률·MTTR 수치를 만들지 않는다.

이 표와 새 수집·일회 비교는 [B-06 완료 판정](B6-completion-gate-20261026.md)을 바꾸지 않는다. 적극적 정상 설명과 배포·실패 경계가 남아 있어 B단계 완료와 C단계 진입은 계속 보류한다.

## v3 순서 입력의 새 보고서 대조 — 2026-10-26 17:10 KST

[진단 비교의 승인된 한 건](B6-normal-sequence-diagnostic-live-result.md)은 위 표를 만든 뒤 별도로 실행했다. 정제 view에 같은 아이템의 miss→hit 두 쌍과 HTTP 200이 들어갔고, 보고서는 각 miss 뒤 hit가 해당 아이템의 제한된 캐시 동작과 일치한다고 설명했다. 누락된 오류 지표를 0으로 채우지 않았으며 자연 TTL·Redis 장애·전체 서비스 정상·복구를 단정하지 않았다. 가용 근거 인용과 `not_executed`도 대조했다. **이 한정 사례의 자체 판정은 `범위 내 적합`**으로 추가한다. 표의 집계 전용 이전 S2 결과와 실패한 첫 v3 실행은 각각 당시 결과로 남긴다. 독립 평가·상시 자동 경로·B-06 완료는 여전히 미검증이다.
