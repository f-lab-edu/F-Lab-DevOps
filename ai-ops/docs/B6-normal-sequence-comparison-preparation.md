이 문서는 준비 당시 기록이다. 이후 해당 ID·해시의 사용자 승인을 받아 [한 건 실행](B6-normal-sequence-live-failure.md)했으나 모델 보고서 계약 검사에서 실패했다. 현재 상태는 `failed`이며 새 예약 $0.10·토큰 계산/생성 각 1회가 발생했다. 초안/세부 검증 사유가 보존되지 않아 의미 평가는 하지 못했고 재전송하지 않았다.

## 구현 흐름

`SequenceComparisonStore`는 v3 출처·view·원본 대응표를 재검증하고 계획·두 요청 본문·프롬프트·실행 코드 해시를 결합한다. 개인 전용 `sequence-comparisons/` 폴더에 HMAC을 붙인 0600 파일과 전체 요청 미리보기를 저장한다. 기존 v1/v2 입력으로 낮춰 처리하지 않는다.

승인은 결합 해시·승인자·공급자 보관 확인·계정 선택적 데이터 공유 꺼짐 확인을 포함하며 30분간 유효하다. 실행 전 상태·코드·입력·키 지문을 재검증하고 한 건 $0.10을 예약한 뒤 토큰 계산/생성을 각 최대 한 번 실행한다. 전송 결과가 불명확하면 `needs_review`로 보존하고 자동 재전송하지 않는다. 기존 `ComparisonStore`의 승인·전송·중복·보관 기능을 상속하며 기존 파일은 수정하지 않았다.

예산은 **기존 `model-comparisons/budget-live.json`**의 잠금과 UTC 일일 $1 장부를 함께 쓴다. mock 장부는 live와 분리한다. v3 폴더를 새로 만들어도 기존 예약은 초기화되지 않는다. 클러스터 캠페인의 장부나 OpenAI 계정 전체 지출을 통합한 한도는 아니다. 본문/미리보기 7일 정리는 명령으로 실행하며, 기존 공유 장부의 본문 없는 이력 90일 정리는 기존 비교 도구의 purge가 담당한다. 자동 스케줄러가 실행 중이라고 가정하지 않는다.
