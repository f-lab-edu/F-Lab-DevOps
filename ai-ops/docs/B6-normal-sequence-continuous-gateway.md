# B-06 정상 캐시 순서의 상시 모델 gateway 연결

기준: 2026-10-26 KST. 상태: **v3 gateway 계약·정책·대기열 연결 구현, 로컬 모의 검증. 정상 관측 CI·전달기·worker의 실제 연결은 구현 전.** B-06 전체 완료 및 C단계 진입 보류는 유지한다.

## 목적과 처리 범위

[정상 캐시 순서의 일회 비교](B6-normal-sequence-diagnostic-live-result.md)에서 사용한 v3 입력을 상시 모델 서비스도 구분해 받을 수 있도록 했다. 같은 아이템의 과거 miss→hit 순서를 설명하는 입력이며, 전체 서비스 정상·자연 TTL 만료·AI 복구 완료를 증명하는 입력은 아니다.

이번에 연결한 구간은 다음과 같다.

1. 검증된 `SequenceProjection`의 원본 probe·아이템 ID·Pod UID·대응표를 제거한다.
2. 정제된 view와 원본 결합 해시·규칙 보고서 참조로 `SequenceModelSubmission(schema_version=3)`을 만든다.
3. 기존 클러스터 내부 gateway 클라이언트가 본문을 서명해 전달한다.
4. gateway가 서명·버전·view 해시·보고서 참조를 검사한다.
5. 승인된 v3 캠페인의 대상·코드·정책·기간과 대조한 후 중복 방지 대기열에 저장한다.
6. v3 프롬프트와 보고서 검사기를 사용해 처리한다. 결과는 의미 검토가 필요한 `needs_review`로 남는다.

이 문서의 검증은 고정 합성 입력과 모의 전송을 사용했다. 새 실습 CI, AWS 변경, 이미지 등록·배포, 새 캠페인 활성화 및 유료 모델 호출을 실행한 기록은 아니다. 이전 일회 비교의 승인도 새 캠페인에 재사용하지 않았다.

## 변경 파일

| 파일 | 역할 |
|---|---|
| `src/ai_ops/model_policy.py` | v1·v2와 함께 v3 view·projection·프롬프트·보고서 검사기를 명시적으로 선택한다. |
| `src/ai_ops/model_gateway_contract.py` | 원본 probe를 제외한 v3 제출 계약과 버전별 파서를 정의한다. 알 수 없는 버전이나 v1로 바꾼 입력은 거부한다. |
| `src/ai_ops/model_gateway_client.py` | 검증된 v3 projection에 맞는 제출 계약을 선택하고 기존 서명 경로로 전송한다. |
| `src/ai_ops/continuous_model.py` | v3의 `base`에서 출처를 읽고 v3 view·해시를 대기열에 결합한다. 순서 정제·프롬프트 코드도 캠페인 구현 해시에 포함한다. |
| `tests/test_model_sequence_gateway.py` | 원본 제외·위변조·버전 혼동·잘못된 출처·미승인 캠페인 거부, 중복 방지, 한 번 처리 및 v3 검토 요청을 검사한다. |
| `tests/test_model_ci_connection.py` | 기존 v2 경로의 회귀 검사에서 지원 버전 v3와 미지원 버전 v4를 구분한다. |

기존 로컬 일회 비교의 코드와 저장 기록은 수정하지 않는다. 상시 캠페인의 구현 해시가 바뀌므로 향후 실제 활성화는 새 이미지·코드·정책에 결합한 새 검토안으로 준비한다.

검증 결과: v3 전용 5개를 포함한 AI 모듈 전체 **496개 시험 통과**. 로컬 HTTP 모의 서버와 고정 자료를 사용했으며 실제 OpenAI 요청은 없다. 전체 실행에서 기존 SQLite 연결의 `ResourceWarning`은 출력됐으나 시험 실패는 없었다. 배포된 실습 경로의 완료 근거로 대체하지 않는다.

## 사용자가 선택한 시작 방식

정상 관측은 **격리 실습 CI에서 시작**한다. 기존 S10의 이미지 실패·원복 기록과 다른 입력 종류로 관리한다. 현재 `CIRelay`는 S10의 `failure` 결과만 접수하고 `ContinuousCIBridge`도 검증된 CI 실패 이력만 처리하므로, gateway의 v3 지원만으로 정상 사례가 자동 접수되지는 않는다.

현재 S10 CI 역할에는 Pod 내부 실행 권한이 없다. 수동 정상 수집기는 실습 API·수집기 Pod 내부 실행, 같은 Pod 로그 및 공유 lease를 사용한다. 따라서 기존 스크립트를 workflow에 넣는 것만으로는 실행할 수 없으며, 아래 순서로 별도 수집 권한과 출처 계약을 구현한다. worker·읽기 수집기에 임의 명령 실행 권한을 추가하는 방식으로 우회하지 않는다.

## 남은 구현 순서

1. **정상 관측 CI 실행자와 권한 고정:** `ai-ops-lab/lab-api`의 자기 데이터 생성·조회·정리, 같은 Pod 로그 읽기, 기존 공유 lease를 사용하는 실행자를 구성한다. S10과 같은 동시 실행 잠금을 사용하고 실패해도 원복을 확인한다. 운영 Deployment 변경은 허용하지 않는다.
2. **원본의 클러스터 내부 보관:** 조회 로그·아이템 ID·원본 snapshot은 클러스터 비공개 저장소에서 검증한다. GitHub artifact에는 정제 결과와 실행·해시 영수증만 보관한다. 임시 CI runner 파일을 원본의 유일한 복구 수단으로 사용하지 않는다.
3. **정상 CI 출처와 큐 접수:** workflow 경로·저장소·main SHA·실행 ID·재실행 번호·artifact digest·관측 시각·대상 UID를 대조하는 별도 계약을 추가한다. 기존 실패·원복 이력으로 위장하거나 성공 결과를 S10 실패로 바꾸지 않는다.
4. **worker 연결과 재시작:** 검증된 정상 관측과 고정 규칙 보고서의 결합을 검사하고 v3 projection을 이번 gateway 경로에 전달한다. 중복·재시작·원복 실패·Pod 교체는 모의 시험으로 먼저 확인한다.
5. **배포와 최소 실측:** CI 검사·이미지 등록 후 모델 기능을 끈 상태에서 배포한다. 새 v3 캠페인의 실제 정제 입력·비용·기간을 검토하고 별도 사용자 승인을 받은 뒤 정상 실습 한 건만 실행한다. 모델 보고서·중복 차단·중지 및 정리를 확인한다.

이번 단계는 위 전체 흐름의 **모델 gateway 수신 구간**이다. 정상 CI부터 보고서까지의 배포 검증 완료로 집계하지 않는다. 다음 작업 권장 추론 깊이: **GPT-6 SOL high**.

후속: [정상 관측 CI 실행자·전용 권한](B6-normal-ci-executor.md)을 코드로 구현했다. 원본 로그의 대조·규칙 조사·v3 정제는 수집기 안에서 수행하고 GitHub에는 정제 영수증만 반환한다. 새 workflow·IAM/RBAC 정의는 아직 실제 활성화 전이며, 현재 수집기 원본 저장은 emptyDir 수명에 한정된다. 전달기·worker의 정상 입력 경로와 실제 모델 자동 처리는 계속 남아 있다.
