## 확인 가능한 실패 범위

`generate_once()`가 응답 완료 상태·모델명·usage·출력 JSON을 검사하고 `draft, usage, model`을 반환한 뒤, `ComparisonStore.run()`의 일반 예외 분기에서 실패했다. 모델 생성 시도의 HTTP 실패나 예산 거부로 기록된 것은 아니다. 다만 실제 검증 예외는 `projection_report_contract_rejected` 하나로 치환돼 **어느 필드나 근거가 잘못됐는지 확정할 수 없다.**

해당 검사는 `ProjectionAnalysisReport` 구조, view와 `input_hash` 일치, 사실·가설의 가용 근거 ID, 가설 근거 존재, diagnosis_status와 가설 유무의 일치를 확인한다. 이 중 하나를 실제 원인으로 단정하지 않는다. 같은 입력의 모의 보고서 통과는 실제 모델 초안의 계약 통과를 보장하지 않는다. 초안을 보존하지 않은 현재 구현의 진단 공백 때문에 이번 모델의 자연어 설명을 평가하거나 복원할 수 없다.

## 다음 작업과 재시도 조건

다음은 **추가 API 호출 없이 실패 진단 보존 기능을 구현·모의 검증**하는 작업이다. 검증 실패를 고정 사유 코드와 오류 필드 경로로 구분하고, 필요 시 크기·권한·보관 기한을 제한한 비공개 초안을 따로 보존한다. Pydantic 오류의 입력값이나 모델 원문을 터미널·Git·공개 HTML에 자동 출력하지 않는다. 잘못된 hash·허위 근거·상태 충돌 초안으로 보존/분류를 시험해 진단 공백을 먼저 해소한다.
