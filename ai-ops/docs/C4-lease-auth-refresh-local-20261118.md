# Lease HTTP401 인증 갱신 · 로컬 수정/검증 (2026-11-18)

## 결과와 확인 범위

로컬 재현·수정·검증 완료. 실제 클러스터/Slack/AWS/GitHub 호출·감시 기동·장애·배포는 하지 않았다. AI/플랫폼 원본의 미커밋 작업과 실행 중인 고정 바이너리·설정은 보존했다. 두 저장소 `codex/lease-auth-refresh-local-20261118`의 `.worktrees/lease-auth-refresh`에서 작업했다. main 반영·원격 CI는 아직 하지 않았다.

실패003에서는 Lease GET HTTP401이 1.752698초에 반환됐고 마지막 계측은 authentication_refresh done이었다. 실제 client-go v0.35.8의 exec RoundTripper는 401 후 maybeRefreshCreds를 호출하고 **원래 401 응답을 그대로 반환**한다. 기존 TrialLeaseClient는 이를 곧바로 실패로 처리한다.

실제 고정 kubectl과 로컬 TLS 서버/가짜 exec 발급기로 이를 재현했다. 최초 정상 조회 후 아직 만료 시각이 남은 자격을 서버가 거절하도록 구성했다. 수정 전에는 새 자격 발급이 완료돼도 첫 조회가401로 실패했고, 별도 다음 GET은 같은 proxy의 새 자격으로 성공했다. 따라서 **갱신 후에도 원래401에서 중단하는 처리 결함**을 확인했다. 실환경에서 최초 자격이 거절된 원인까지 증명한 것은 아니며, 로컬 결과를 실환경 해결 완료로 확대하지 않는다.

## 변경

- 완전한 Kubernetes Status/Unauthorized 응답을 받은 고정 Lease GET만 최대1회 새로 조회한다. 같은 proxy/기존 인증 경로를 사용하며 인증 성공이나 승인 결과를 만들어 내지 않는다.
- 최초 호출 시 단조 시계로 3초 deadline을 고정한다. 연결·헤더·본문·재조회가 같은 남은 시간을 사용한다. 느린 본문이 timeout을 계속 초기화하지 않으며 성공 반환 전에도 기한을 확인한다. 대기/backoff/예산 확대 없음.
- PUT/CAS·403·일반 서버/통신 오류·잘린/잘못된 응답은 재실행하지 않는다. 재조회에서도401이면 중단한다. UID/namespace/name/resourceVersion·응답 크기 검사를 그대로 적용한다.
- 마지막 실패에는 인증 재조회 횟수2/최초HTTP401만 허용 목록으로 전달한다. 원문 토큰·헤더·응답·exec 오류 문자열은 남기지 않는다. 재조회 성공 결과는 `last_auth_retry`에서 확인할 수 있다.
- 실패/재조회 시 HTTPResponse와 연결을 즉시 닫는다. 기존 종료·자기 proxy/socket/reader 회수와 SIGTERM 전달을 유지한다.
- AI와 플랫폼의 구현/새 시험/로컬 TLS 재현 스크립트는 byte 단위 동일하다. 기존 CI에 일반 kubectl 로컬 인증 시험을 추가했고 AI 계측 job에도 추가했다. 실제 CI는 실행하지 않았다.
