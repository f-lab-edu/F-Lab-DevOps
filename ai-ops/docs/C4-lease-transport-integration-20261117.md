# Lease 연결 진단과 잘린 HTTP 응답 거절 검토

Lease GET/PUT가 실패할 때 오류 단계·고정 원인 분류·소요 시간·HTTP 상태·proxy 종료 코드를 기록한다. 기존 오류 문자열과 ValueError 호환을 유지하며 비밀값·예외 원문·헤더·응답·kubeconfig·proxy stderr는 출력하지 않는다. 응답 본문이 Content-Length를 채우지 못하면 완전한 JSON이어도 성공으로 사용하지 않는다.

검토 범위는 연결/응답/본문 종료, 실패 로그의 비밀 비출력, 출력 장애가 원래 중지를 가리지 않는지, CAS 충돌과 불확실한 PUT의 재전송 금지, UID/TLS/조회 필터와 취소 정리다. 새 로컬 Unix 서버 회귀 9개와 실제 kubectl v1.35.8·로컬 TLS upstream 지연 시험을 포함한다. 자동 재시도나 캐시 성공 응답은 추가하지 않는다.

3초 조회, 시작15초·안내후 최소120초/시작후210초 리뷰·소유원복240초/독립원복 시작300초·회복관찰120초와 실행별 승인·정확한 head 실제 사람 리뷰/CI·UID/Lease·회수 조건은 유지한다. 제어 workflow·권한·타깃·기한 계약은 변경하지 않는다. 실제 C04 감시 기동·장애·PR 자동 실행은 이 변경에 포함되지 않는다.

로컬 대역은 헤더 지연과 본문 지연이 기존 동일 오류로 합쳐지던 동작과, 잘린 HTTP의 잘못된 성공 수용을 재현했다. 당시 실환경 연결 실패의 정확한 원인은 남은 원본 로그로 확정할 수 없으며, 수정 후 장애 없이 읽기 전용으로 조사한다. 로컬 timeout 재현을 실환경 원인 확정으로 간주하지 않는다.

코드 변경은 Lease client·로컬 TLS 검사·새 회귀 시험이다. 플랫폼은 기존 테스트 기반을 유지하고 이 수정만 가져온다. AI와 플랫폼의 Lease client 파일은 동일하게 유지하며, 새 불변 runtime은 각 반영된 전체 SHA와 hash 계약을 사용해야 한다. 과거 runtime/승인/readiness/standby 증거를 재사용하지 않는다.
