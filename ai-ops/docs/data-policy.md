# A0 데이터 출처와 보관 기준

- 확인일: 2026-09-27
- 적용 범위: A1 데이터 계약·A2 로컬 증거 처리·A3/A4 개인 저장소·A5 합성 증거 전용 모델 입력 및 향후 평가·런북 입력. B-02 수집기·규칙 조사 연결은 모의 API로 검증했다. 실제 클러스터 적용과 captured 자료의 외부 전송은 별도 검토·실환경 검증이 남았다.

## 1. 출처 구분

| 자료 | 기록할 출처 | 사용 기준 |
|---|---|---|
| 런북 | document_id, version, SHA-256, 검증 Git SHA, 확인일, 근거 코드 경로/hash | index 등록·코드 대조 완료 문서만 입력 후보 |
| 실제 수집 자료 | provenance=captured, 환경/대상, 관측·수집 UTC 시각, 수집 도구·버전, 마스킹 요약 | 수집 허용 범위와 공개·모델 전송 범위를 확인한 뒤 사용 |
| 합성 자료 | provenance=synthetic, fixture 버전, 가상 대상·타임라인, 생성 목적 | 실제 운영 사건·성과로 표현하지 않음 |
| 누락 자료 | source와 missing/permission_denied/stale/invalid 이유 | 빈 자료를 0·정상으로 바꾸지 않음 |

실제·합성 자료가 섞인 bundle은 증거 항목별 출처를 남긴다. 수집 시각을 사건 발생 시각으로 대체하지 않는다. 코드 검토와 Helm 렌더링은 실환경 관측 자료가 아니다.

## 2. 보관과 모델 입력

- 원시 로그·Secret·credential 포함 URL·실제 결과는 저장소 밖의 사용자 지정 디렉터리에 두고 사용자 접근을 제한한다. A3의 `--store`는 정제된 입력·결과 전용 개인 디렉터리이며 원시 자료 보관 위치로 사용하지 않는다.
- 원시 자료 수집에는 허용된 목적·최소 범위를 적용한다. Secret 전체 덤프나 설정 URL 출력으로 구성 의도를 확인하지 않는다.
- repository에는 사람이 검토한 마스킹 fixture·런북·익명 평가 결과만 둔다. 질문·로그·도구 인자/결과·audit·보고서도 민감정보 검토 대상이다.
- 정답·채점 기준은 agent 도구 접근 경로 밖에 둔다. holdout을 개발/엔진 선정에 사용하면 개발 데이터로 전환하거나 새 평가 입력을 준비한다.
- 런북 index는 허용 목록이다. README·실습 문서 전체 자동 검색은 허용 입력 정책이 아니다.
- A5의 외부 모델 입력은 `practice` 대상의 합성 증거로만 제한한다. 기존 API 키 경로의 모델은 OpenAI `gpt-6-sol`, 설정 예산은 건당 $0.10·UTC 일일 $1이다. Plus 연동은 비채택이며 사용하지 않는다. 캡처한 운영 자료의 전송 허용 여부는 별도로 결정해야 한다.

## 3. 갱신과 삭제

관련 코드/hash가 달라지면 런북을 재검토한다. 문서 내용 변경 시 version/hash를 갱신하고 확인 근거를 남긴다. 파일 hash는 동일성을 확인하며 내용 정확성·마스킹 완전성을 입증하지 않는다.

실제 자료를 도입하기 전에 보관 기간·삭제 책임·파생 보고서/audit 삭제 범위를 확정한다. 현재는 실제 원시 자료와 실행 결과를 생성하지 않았으며 보관 기간이 확정된 것으로 표현하지 않는다.


## 4. B-02 기본 거부 구현 — 2026-10-16

`data_policy.py`의 공통 모델 정책을 조사 저장 진입점·고정 증거 AI·도구 탐색 AI·재생 실행기에 적용했다. practice synthetic만 모델 입력으로 허용하며 captured·혼합·production은 모델 전송 전에 거부한다. B CLI는 규칙 모드만 제공하고 키·비용 장부를 사용하지 않는다. 이 구현은 provenance 표기와 무결성 검증에 기반하므로 실제 자료를 synthetic으로 위장하는 행위를 자동 식별하지는 못한다.

B snapshot은 hash를 재검증하고 설정 hash·query catalog hash·대상·증거 ID·상태·시각·정규화된 허용 필드가 감사와 맞아야 로컬 저장한다. 감사는 input의 bundle hash 및 metadata의 감사 hash와 연결하며 저장소 밖 0700 경로의 0600 파일로 보관한다. 원시 응답은 저장하지 않는다. 수집 누락은 규칙 부분 결과로 표시하고, 재조회에서도 partial·최신 상태 판정의 정합성을 확인한다.

captured 전송 허용 정책·별도 B AI 프롬프트와 `snapshot-fixed-v1` 후보 연결은 아직 구현/활성하지 않았다. 실제 개발 샘플의 선별·개인정보 제거·대상/필드/보관 정책을 검토한 뒤 별도 version으로 추가해야 한다. 실환경 자료의 보관 기간·삭제 작업도 B 후속 검증 대상이다.

## 5. 실제 수집 파일럿 범위 — 2026-10-19

등록한 production 앱을 규칙 모드로만 제한 수집한다. 이번 검증 자료의 보관 기준은 생성 후 7일, 책임은 저장소 운영자이며 암호화 PVC의 보관표에 UTC 삭제 기한·범위를 기록한다. 자동 삭제는 미구현이다. 원시 응답은 메모리에서만 처리하고 정제된 자료·보고서·감사는 0700/0600 경로에 보관한다. 외부 모델 전송은 계속 차단하고 repository에는 고정 상태·누락 사유·건수·해시만 기록한다. 오래된 이력·목록 응답 호환 오류를 수정한 이미지에서 실제 규칙 부분 보고서 저장·재조회를 완료했다. 최종 실행의 삭제 기한은 2026-10-26 18:12:10 KST이며 보관표는 UTC로 남긴다. 상세 범위와 삭제 대상은 [실환경 검증 문서](B2-live-validation.md)를 따른다.
