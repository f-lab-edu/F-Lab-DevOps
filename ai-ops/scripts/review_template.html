검토자와 저장

식별자는 실명 대신 reviewer-01처럼 적어도 됩니다. 작성에 참여하지 않은 경우에만 독립 검토 확인을 선택하세요. 입력은 이 브라우저에 임시 저장되지만, 중간에는 ‘현재 초안 JSON 저장’으로 백업하는 편이 안전합니다. 화면이 갱신됐거나 새로고침해야 한다면 먼저 초안을 저장하세요. 파일을 다시 열 때는 같은 패킷의 초안만 불러올 수 있습니다.

완료 파일은 브라우저의 다운로드 폴더에 저장됩니다. 이 파일을 평가 담당자에게 전달하면 A/B의 실제 방식 이름을 복원해 점수에 반영합니다. 화면 자체나 원본 JSON을 공개 웹사이트에 게시하지 마세요.

원본 자료(증거)

각 줄을 누르면 해당 자료의 내용이 열립니다. ‘사용 가능’인 자료의 실제 내용과 보고서의 인용 문장을 비교하세요. ‘누락·접근 거부·오래됨’은 왜 읽을 수 없는지를 나타냅니다. 자료 번호가 보고서에 적혀 있어도 문장의 뜻이 맞는지는 별도 확인이 필요합니다.

아래 보고서 A와 B를 각각 채점합니다. 순서나 문체로 방식 이름을 추측해 점수를 바꾸지 마세요. 첫 원인 후보는 ‘원인 가설’의 첫 줄입니다.

무엇을 하는 화면인가요?

가상의 서비스 운영 상황 16개에 대해 AI가 쓴 설명문 두 개를 원본 자료와 비교하는 화면입니다. 한 상황을 여기서는 사건, 원본 자료를 증거, AI의 설명문을 보고서라고 부릅니다. 사건마다 보고서 A와 B를 각각 읽고, 내용이 맞는지 판정해 주세요. 총 32개 보고서를 검토합니다.

A/B는 조사 방식의 이름을 숨긴 표시입니다. 어느 쪽이 어떤 방식인지 알 필요가 없고, 둘 중 하나를 반드시 고를 필요도 없습니다. 두 보고서 모두 맞거나 모두 틀릴 수 있습니다. 이 자료는 실제 클러스터 장애가 아닌 합성 예시입니다.

검토 순서

  1. 사건 기준 읽기: 사건 번호와 유형(장애·정상·증거 부족), ‘첫 원인 후보 기준’과 ‘금지 주장’을 확인합니다. 정상·증거 부족 사건의 Top-1은 채점하지 않습니다.
  2. 증거 열기: 출처·상태·관측 시각과 실제 내용을 확인합니다. 수집 시각은 확보한 때라 관측 시각과 다를 수 있습니다. 누락·접근 거부·오래된 자료의 값을 0으로 보지 않습니다.
  3. 보고서 A와 B를 각각 읽기: 관측 사실·인용 ID·원인 가설·한계·제안을 각 원본과 대조합니다. 제안 조치를 실행 완료로 잘못 읽지 않습니다.
  4. 첫 원인 후보 판정: 장애 사건에서는 ‘원인 가설’ 첫 줄이 구체적 기준과 같으면 ‘맞음’, 없거나 다르면 ‘틀림’을 고릅니다. 뒤의 가설이 맞아도 첫 후보를 맞은 것으로 세지 않습니다.
  5. 근거 의미 판정: 사실·가설 문장이 모두 인용 자료의 내용과 시각에 맞는지 확인합니다. 인용 ID만 있거나 일부만 맞으면 ‘맞음’이 아닙니다. 증거 부족이면 없는 값을 만들어내지 않고 판단을 유보했는지도 봅니다.
  6. 금지 주장 판정: 화면의 금지 주장과 뜻이 같은 단정이 보고서 어디에든 있으면 ‘있음’을 고릅니다. 같은 단어를 쓸 필요는 없습니다. ‘있음’은 결함입니다.
  7. 이유와 저장: 맞다고 판단해도 비교한 증거 ID와 보고서 문장을 적습니다. 사용 가능 증거가 없으면 그 상태와 유보 문장을 적습니다. 16건의 A/B를 마치고 ‘완료 32/32’를 확인한 뒤 식별자와 독립 검토 확인을 입력해 완료 JSON을 저장합니다.

간단한 예: 원본 로그에 ‘인증 정보가 거부돼 캐시 읽기가 실패했다’고 적혀 있는데 보고서가 ‘Redis 전체가 중단됐다’고 단정하면, 인증 문제를 맞혔더라도 금지 주장에는 ‘있음’을 고릅니다. 인용 ID가 존재한다는 이유만으로 문장까지 맞는 것은 아닙니다.

애매한 경우 판정 이유에 불확실성을 구체적으로 남깁니다. 검토 중에는 기존 A7 결과 화면이나 자체 검토 점수를 참고하지 마세요. 이미 보았다면 판정 이유나 별도 전달 메모에 밝혀 주세요.

부록 · 화면 용어 풀이

사건(case)
특정 서비스와 시간대를 잘라 만든 가상의 조사 문제 한 건입니다. case-01 같은 번호는 이름표일 뿐, 장애 종류를 뜻하지 않습니다.
증거(evidence)
그 시간대에 저장된 로그·지표·배포 기록 등 원본 자료입니다. ev-… ID는 보고서 문장과 원본을 연결하는 표식입니다.
보고서 A/B
동일한 사건을 서로 다른 AI 조사 방식으로 설명한 결과입니다. A/B 배정은 사건마다 섞이며 각 보고서 옆에는 실제 방식 이름을 표시하지 않습니다.
판정
검토자가 보고서의 첫 원인, 근거 문장, 금지 주장을 원본 자료와 비교해 ‘맞음/틀림’ 또는 ‘있음/없음’을 고르는 일입니다. AI의 자기 평가가 아닙니다.
관측 사실 · 원인 가설
관측 사실은 원본에 기록된 내용, 원인 가설은 그 사실로 추론한 가능한 이유입니다. 가설은 사실이나 복구 완료 선언과 구분해야 합니다.
지표 · 로그 · 이벤트
지표는 횟수·시간 같은 수치 기록, 로그는 프로그램이 남긴 문장, 이벤트는 클러스터가 남긴 상태 변화 기록입니다. 설정 요약·배포 기록·워크로드 상태도 원본 자료의 종류입니다.
원인 판단 · 서비스 상태
원인 판단은 AI가 이유를 추정했는지, 장애를 확인하지 못했는지, 판단을 유보했는지를 뜻합니다. 서비스 상태는 영향 있음·정상·복구됨·알 수 없음 중 보고서가 기록한 값이며, 실제 현재 클러스터 상태와 같다는 보장은 없습니다.
첫 원인 후보(Top-1)
보고서 ‘원인 가설’의 맨 첫 항목입니다. 장애 사건에서만 화면의 구체적인 기준과 비교합니다. 첫 항목이 없거나 다른 원인이면 ‘틀림’입니다.
필수 증거 ID · 인용 ID
필수 증거 ID는 판단에 특히 중요한 자료의 표식입니다. 인용 ID는 보고서가 근거로 붙인 표식입니다. 번호가 같아도 문장 내용이 원본과 맞는지는 따로 살펴야 합니다.
증거 부족 · 판단 유보
자료가 없거나 오래됐거나 접근이 막혀 원인을 결정할 수 없는 상태입니다. ‘모르겠다’는 판단이 맞을 수 있으며, 없는 값은 0이나 정상으로 바꾸면 안 됩니다.
관측 시각 · 수집 시각
관측 시각은 실제 상태가 기록된 때, 수집 시각은 그 자료를 확보한 때입니다. 화면은 읽기 쉽게 KST를 표시하고, 원본 JSON의 Z는 UTC(+00:00), KST는 UTC+09:00입니다.
JSON · null · []
JSON은 기계가 읽는 자료 형식입니다. null은 값이 없다는 뜻이고 []는 목록에 항목이 없다는 뜻입니다. 둘 다 오류나 지표 값 0이라는 뜻은 아닙니다.
제안 조치
보고서가 나중에 확인하거나 수행하자고 제안한 일입니다. 이 평가에서 실제 서버를 바꾸거나 조치를 실행하지 않았습니다.

평가 범위와 현재 상태

새 v3 합성 사건 16건에서 두 AI 방식의 첫 반복 보고서 32건을 검토합니다. 장애 8건의 첫 원인 후보, 모든 보고서의 근거·판단 유보 진술과 금지 주장을 원본 증거에 대조합니다. 독립 판정은 아직 받지 않았습니다. 자료와 프롬프트를 작성한 사람의 자체 검토는 독립 결과로 합산하지 않습니다.

이 화면은 로컬 전용이며 Git에 포함하지 않습니다. 사건별 A/B 배정은 무작위이고 실제 방식 대응표는 저장소 밖에 권한 0600으로 보관합니다. 사건 유형과 고정 기준은 보이며, 아래 담당자용 명령에는 두 방식의 파일명도 드러납니다. 숨긴 것은 각 보고서와 방식의 대응 관계입니다. 문체로도 방식을 추측할 수 있어 완전한 블라인드 검증은 아닙니다. 자료 작성자가 이전 오답을 알고 있었다는 한계도 있습니다.

검토자에게 전달할 자료

평가 담당자는 생성된 이 HTML 파일 하나만 별도 검토자에게 전달합니다. 기존 A7 결과 화면, 방식 대응표, 자체 검토·자체 점수 파일과 API 키는 전달하지 않습니다. 이 HTML은 외부 네트워크나 AI 모델을 호출하지 않고 열 수 있습니다. 평가용 합성 로그가 포함되어 있으므로 공개 웹사이트에 게시하지 않습니다.

검토자는 이름 또는 식별자를 입력하고 자료 작성에 관여하지 않았다는 확인 항목을 선택합니다. 중간에는 초안 JSON을 저장·복원할 수 있습니다. 이 화면을 새로고침하기 전에는 초안 JSON을 먼저 저장하세요. 32개 판정과 이유를 완료하면 완료 JSON을 평가 담당자에게 전달합니다.

평가 담당자용 · 생성과 결과 반영

AI_OPS_EVAL_STORE는 기존 개인 평가 저장소, AI_OPS_PYTHON은 잠금 의존성을 설치한 Python을 가리킵니다. 아래 생성 명령은 저장된 보고서를 읽으며 모델 또는 유료 API를 호출하지 않습니다. 저장소 루트에서 실행합니다.

PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/prepare_blind_review.py prepare \
  --fixed-packet "$AI_OPS_EVAL_STORE/a7-v3-fixed-review-packet.json" \
  --ai-packet "$AI_OPS_EVAL_STORE/a7-v3-ai-review-packet.json" \
  --html ai-ops/site/a7-review.html \
  --mapping "$AI_OPS_EVAL_STORE/a7-v3-blind-review-map.json"

새로 생성하면 A/B 배정과 패킷 ID가 바뀝니다. 생성기는 기존 HTML·대응표를 덮어쓰지 않으므로 새 패킷에는 두 파일 모두 다른 이름을 지정해야 합니다. 검토자가 결과를 작성한 패킷의 대응표는 반드시 보존합니다.

완료 JSON을 저장소 밖 개인 저장소의 a7-v3-independent-review.json으로 옮긴 뒤 아래처럼 변환합니다. 변환기는 패킷 ID, 32개 판정, 독립 검토 확인과 필수 이유를 검사하고 방식별 기존 채점기 형식으로 분리합니다.

PYTHONPATH=ai-ops/src "$AI_OPS_PYTHON" ai-ops/scripts/prepare_blind_review.py import \
  --review "$AI_OPS_EVAL_STORE/a7-v3-independent-review.json" \
  --mapping "$AI_OPS_EVAL_STORE/a7-v3-blind-review-map.json" \
  --fixed-template "$AI_OPS_EVAL_STORE/a7-v3-fixed-review-template.json" \
  --ai-template "$AI_OPS_EVAL_STORE/a7-v3-ai-review-template.json" \
  --fixed-output "$AI_OPS_EVAL_STORE/a7-v3-fixed-independent-review.json" \
  --ai-output "$AI_OPS_EVAL_STORE/a7-v3-ai-independent-review.json"

독립 완료 JSON을 받기 전에는 독립 점수를 계산하거나 A/B 실제 방식을 공개하지 않습니다. 변환 후 각 방식의 실행 결과와 해당 독립 검토표를 score_holdout.py에 각각 입력합니다. 첫 반복 Top-1은 장애 8건의 방식별 점수로 합산할 수 있지만, 근거 의미의 전체 48회 비율은 2·3회차 검토 전까지 대기입니다. 자체 검토와의 차이를 사건별로 확인하고 결과를 보고 프롬프트나 평가 자료를 바꾸면 v3를 개발 자료로 재분류합니다.
