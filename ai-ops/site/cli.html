A3의 명령줄 사용법입니다. 현재 저장된 증거로만 규칙 조사를 실행합니다.

AI 운영 조사 CLI 명령어

증거 확인 → 규칙 조사 → 보고서 다시 보기

2026-09-30 기준 · A3 로컬 구현

CLI는 터미널에서 명령어를 입력하는 방식입니다. --question 같은 표시는 뒤의 값을 프로그램에 전달하는 옵션 이름이며, 질문 문장에 포함되지 않습니다.

아래 예시는 저장소 루트에서 실행합니다. Python 3.11 이상과 고정 의존성이 설치되어 있어야 합니다. 패키지를 설치한 환경에서는 PYTHONPATH=ai-ops/src python3 -m ai_ops 대신 aiops를 사용할 수 있습니다.

명령어 세 가지

모든 예시의 --bundle은 저장된 증거 폴더, --registry는 조사 허용 대상 목록입니다.

  1. validate-bundle — 증거 파일과 manifest를 검사하고 대상·시간·증거 상태를 출력합니다.
  2. investigate — 검증된 증거로 규칙 기반 보고서를 만들고 사건 ID·실행 ID를 출력합니다.
  3. show — 저장된 사건의 실행 결과를 다시 보여줍니다.

1. validate-bundle · 증거 검사

조사 전에 합성 또는 저장된 증거 묶음의 경로, 해시, 등록 대상, 시각과 형식을 확인합니다. 보고서나 사건 기록은 만들지 않습니다.

PYTHONPATH=ai-ops/src python3 -m ai_ops validate-bundle \
  --bundle ai-ops/evals/fixtures/dev/s1-cache-error \
  --registry ai-ops/config/targets.example.json
--bundle 필수
검사할 증거 묶음 폴더. 그 안의 manifest.json과 원본 파일을 읽습니다.
--registry 필수
대상 허용 목록 JSON 파일. 묶음의 클러스터·네임스페이스·워크로드를 대조합니다.

2. investigate · 규칙 조사

증거를 다시 검증하고 캐시·DB·배포 등에 대한 미리 정한 조건으로 보고서를 만듭니다. 질문의 비밀값을 마스킹해 요청에 보관하지만, 현재 규칙 엔진은 질문 문장을 자연어로 해석해 판단을 바꾸지 않습니다.

PYTHONPATH=ai-ops/src python3 -m ai_ops investigate \
  --bundle ai-ops/evals/fixtures/dev/s1-cache-error \
  --registry ai-ops/config/targets.example.json \
  --store /private/tmp/aiops-my-store \
  --request-id demo-s1-001 \
  --question '캐시 오류와 사용자 영향의 근거를 정리해줘'

--mode rules는 기본값이므로 생략했습니다. 명시해도 같은 결과를 얻습니다.

--bundle 필수
조사할 증거 묶음 폴더.
--registry 필수
조사 허용 대상 목록.
--store 필수
사건·실행·보고서를 저장할 개인 로컬 폴더. 저장소 밖의 사용자 소유 폴더여야 하며 디렉터리는 0700, 저장 파일은 0600 권한으로 관리합니다. 위 /private/tmp/...는 임시 실습 예시입니다.
--request-id 필수
사용자가 정하는 요청 식별자. 같은 ID와 같은 입력을 다시 보내면 기존 사건·실행을 반환하고, 같은 ID에 다른 입력을 주면 거부합니다.
--question 필수
조사를 요청하는 문장. 예시처럼 따옴표로 감싸 공백을 포함할 수 있습니다.
--mode 선택
기본값은 rules입니다. ai라는 값은 예약되어 있지만 A5 이전에는 오류로 거부합니다.

완료되면 터미널에 사건 ID와 실행 ID가 표시됩니다. 다음 show 명령에서 두 값을 사용합니다.

3. show · 결과 다시 보기

investigate가 출력한 사건 ID와 실행 ID로 저장된 보고서를 엽니다. 아래 꺾쇠 괄호 부분은 실제 출력된 값으로 바꿔 입력합니다.

PYTHONPATH=ai-ops/src python3 -m ai_ops show \
  --store /private/tmp/aiops-my-store \
  --incident '<출력된 사건 ID>' \
  --run '<출력된 실행 ID>'
--store 필수
investigate에서 사용한 동일한 개인 저장 폴더.
--incident 필수
출력된 사건 ID.
--run 필수
출력된 실행 ID.
--format 선택
기본값 markdown은 사람이 읽는 보고서와 KST 시각을 표시합니다. --format json은 UTC 시각의 원본 보고서 JSON을 출력합니다.

현재 기능의 범위

이 명령어는 저장된 증거를 로컬에서 읽고 분석합니다. AI 모델이나 실시간 EKS 클러스터에 연결하지 않으며, Pod 재시작·배포 수정 같은 조치를 실행하지 않습니다. 규칙 보고서는 관측 사실과 원인 후보를 구분하고, 증거가 부족하면 판단을 유보합니다.
